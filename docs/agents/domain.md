# Domain Docs

This is a single-context repository. Before exploring a domain area, read `CONTEXT.md` at the repository root if it exists, then read any relevant decisions in `docs/adr/`.

The domain glossary should use the project's existing vocabulary for datasets, training tasks, adapters, base models, inference services, and providers. If a new term or unresolved boundary appears, record it through the domain-modeling workflow instead of silently inventing competing terminology.

If these files do not exist yet, proceed with the repository's existing documentation and create them only when a domain decision is actually resolved.
