# Antfu UI 基础层与逐页迁移设计

日期：2026-09-05
状态：待用户审核

## 1. 目标

在不改动后端 API、训练执行器、数据库和优云 Provider 的前提下，建立一套可复用的前端 UI 基础层，统一训推平台的导航、页面头部、工具栏、状态、指标、表格、空状态和确认弹窗，并逐页迁移现有页面。

本设计采用 antfu Skill 的工程约束：组件单一职责、类型与常量显式抽离、减少隐式魔法和 CSS 覆盖链，不引入新的 UI 框架或自动导入机制。

## 2. 现状与边界

### 2.1 当前问题

- `app/globals.css` 同时承载基础令牌、历史页面样式和后续参考控制台样式，选择器覆盖链较长。
- 概览、数据集、微调任务、模型管理、推理服务存在重复的标题、工具栏、状态和空状态实现。
- 中等宽度或浏览器高缩放场景下，固定侧栏与内容区的关系不够明确，容易产生“页面只显示左侧”的误解。
- 训练、实例、模型和推理状态的展示语义不完全统一。

### 2.2 不在本次范围

- 不修改 FastAPI 路由、API 响应契约、数据库模型、训练执行器和优云调用。
- 不启动真实 GPU、vLLM、优云实例或训练任务。
- 不改变任务状态机、实例释放策略和模型可用性判定。
- 不做全量业务重写；只做影响 UI 一致性和可操作性的必要拆分。

## 3. 设计方案

### 3.1 设计令牌

在 `app/globals.css` 保留现有视觉基调，整理为统一令牌：

- 颜色：背景、表面、边框、正文、次要文字、品牌、成功、警告、危险。
- 尺寸：4/8/12/16/20/24/32 间距体系。
- 控件：按钮最小高度、输入框高度、图标按钮尺寸、圆角和焦点环。
- 布局：侧栏宽度、内容最大宽度、页面内边距、表格最小宽度。

新增样式优先使用令牌，不在组件内写散落的颜色和尺寸常量。

### 3.2 共享组件

新增或整理以下前端组件，每个组件只负责一个界面契约：

- `PageHeader`：标题、描述和主操作。
- `Toolbar`：搜索、筛选、刷新和辅助操作。
- `StatusBadge`：统一状态颜色、文字和可选更新时间。
- `MetricCard`：指标值、标签和趋势/来源说明。
- `EmptyState`：加载中、无数据、筛选无结果、错误四种状态。
- `SectionPanel`：统一面板标题、辅助说明和内容区域。
- `ConfirmDialog`：停止、删除、归档等危险操作确认。
- `ResponsiveTable`：表格滚动、空状态、操作列和窄屏策略。

组件的 props 类型放入同文件顶部或相邻 `lib/ui-types.ts`，不使用复杂内联匿名类型。

### 3.3 页面迁移顺序

1. `PlatformShell` 与全局布局：导航、内容宽度、焦点和响应式。
2. 概览：指标卡、活动任务、异常和动态列表。
3. 数据集：列表工具栏、状态、空状态、详情入口。
4. 微调任务：创建页、任务表格、详情和日志状态。
5. 模型管理：统一标签页、模型表格、详情和待处理状态。
6. 推理服务：服务列表、创建表单、详情和 API 信息。
7. 视觉理解与文生图：复用创建表单、资源选择和上传区域。

每一步只迁移一组共享模式，避免一次修改多个业务状态逻辑。

## 4. 交互契约

- 主操作使用实心品牌按钮；次操作使用描边按钮；危险操作使用危险按钮。
- 图标按钮必须具备 `title` 或 `aria-label`，不以裸字符作为唯一语义。
- 禁用按钮必须在邻近区域说明阻塞原因；前端不自行推断后端状态。
- 异步操作显示进行中状态，组件卸载后不得继续更新状态。
- 页面必须区分加载中、无数据、筛选无结果、错误和成功状态。
- 训练、实例、模型和推理状态均显示后端返回的真实来源；没有数据时显示“暂无数据”，不显示伪造的 0。

## 5. 响应式契约

- 1440px：216px 侧栏、内容区最大宽度 1400px，表格操作完整可见。
- 1024px：内容区缩小但不被侧栏遮挡，复杂表单允许双列。
- 700px 以下：表单单列、工具栏换行、操作按钮堆叠，表格保留横向滚动。
- 390px：标题和按钮不重叠；弹窗不超出视口；输入与按钮可触达。
- 浏览器高缩放触发窄屏断点时，布局仍保持可理解，不出现内容被固定侧栏遮挡的情况。

## 6. 数据与 API 边界

UI 继续通过现有统一 API client 调用后端。共享组件只接收已经解析的前端类型，不直接请求 API，不访问文件系统、优云、ModelScope、MinIO 或 SSH。

状态、日志、Loss、价格、实例和模型可用性全部由页面上层获取并传入；组件只负责展示和触发回调。

## 7. 测试与验收

### 7.1 最小失败测试

- 共享组件在无数据、加载、错误和筛选无结果时显示正确状态。
- 主按钮、危险按钮、禁用按钮具备稳定语义和可访问名称。
- 侧栏在 1440px、1024px、700px、390px 下不遮挡主内容。
- 训练创建页底部操作区在窄屏下不被内容覆盖。

### 7.2 验收命令

```text
npm run test:frontend
npx tsc --noEmit
npm run build
```

必要时使用浏览器检查概览、数据集、视觉理解训练、文生图训练、模型管理和推理服务六类页面。

### 7.3 回滚

每个迁移批次保持文件边界清晰；出现回归时只回滚当前共享组件和对应页面迁移，不回滚用户已有业务改动，不触碰后端和数据。

## 8. 实施顺序

1. 先新增令牌和共享 UI 组件，并为其写最小回归测试。
2. 迁移 `PlatformShell` 和概览页，验证桌面/窄屏布局。
3. 按页面顺序迁移其余模块，每批执行前端测试和 TypeScript 检查。
4. 全部迁移完成后执行生产构建，并进行浏览器验收。
