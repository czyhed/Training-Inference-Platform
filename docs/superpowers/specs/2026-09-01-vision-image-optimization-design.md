# 视觉理解与文生图功能优化设计

**日期：** 2026-09-01  
**状态：** 待用户审阅

## 目标

把视觉理解和文生图的训练/推理流程提升到与 NLP 训练模块一致的可观测、可恢复和可验收水平，重点保证远端实例不泄漏、任务状态可信、日志与 Loss 持久完整、失败可诊断，随后统一任务列表与详情交互。

## 范围

### 包含

- 视觉理解微调任务的状态、日志、Loss、产物和优云实例生命周期。
- 文生图微调任务的状态、日志、Loss、产物和优云实例生命周期。
- 文生图推理任务的预检、远端实例、生成结果、样本级状态和清理生命周期。
- 两类任务的列表、筛选、详情、操作反馈和错误提示。
- 历史任务中陈旧实例状态的只读核对与可重试清理。

### 不包含

- 新增模型训练算法、分布式训练或多卡调度。
- 改变已有 NLP 任务的核心训练实现。
- 把优云账号、密钥或原始远程命令暴露给浏览器。
- 未经确认的批量删除历史任务或远端实例。

## 现状与问题

现有代码已经有独立的视觉理解、文生图训练和文生图生成运行时，并具备 Fake 执行器、优云资源选择、预检、重试、删除、日志和指标字段。但三条流程的字段和展示方式不完全一致：视觉任务的历史实例标记可能停留在 `awaiting_comparison`，文生图历史记录可能只有 `remoteHandle` 而缺少完整清理结果；前端详情页也没有统一地呈现资源状态、阶段、日志、Loss、产物和失败建议。

NLP 模块提供本项目内的功能基线：明确的状态阶段、任务操作矩阵、持续日志、Loss/Eval Loss 曲线、Best/Final Adapter 选择、克隆/重试/删除和可操作错误提示。外部参考站点 `http://185.61.210.32:13101/` 作为统一控制中心的布局与状态聚合参考，不作为训练业务接口或数据模型来源。

## 设计原则

1. **资源事实优先：** 远端实例查询结果高于历史任务标记；任务终态不能掩盖仍存在的优云实例。
2. **状态单向且幂等：** 停止、失败、重试、清理和删除可重复调用，不创建重复实例。
3. **服务端持久化为准：** 页面刷新或后端重启后，日志和指标仍可恢复；列表只返回摘要，详情返回完整数据。
4. **失败可行动：** 每个失败都分类，并给出用户下一步动作。
5. **不破坏现有任务：** 保留当前 API 兼容字段，历史任务采用渐进式补齐而非删除。

## 架构

### 统一任务生命周期

视觉理解、文生图训练和文生图生成继续使用各自运行时，但补充共同的生命周期语义：

```text
awaiting_confirmation
        -> queued -> preparing/provisioning -> running
        -> collecting -> completed
                         -> failed / stopped
任何远端阶段 -------------------------------> cleanup -> released
```

每个远端任务都维护以下信息：

- `provider`、`executionMode`、`instanceId`、`remoteHandle`。
- `resourceState`：`none`、`provisioning`、`running`、`stopping`、`released`、`cleanup_failed`。
- `cleanupState`：`pending`、`released`、`failed`。
- `cleanupError`、`cleanupCheckedAt` 和可重试清理动作。

字段名称保持与当前 API 兼容；新增字段只在服务端和前端共同使用的响应中出现。

### 启动与重启核对

- 后端启动时扫描本地任务记录，找出未处于 `released` 的远端句柄或实例标记。
- 通过 `DescribeCompShareInstance` 核对实例是否存在以及当前状态。
- 实例不存在时，将资源状态修正为 `released`，保留历史任务并写入核对时间。
- 实例仍存在时，不自动删除；任务详情显示“远端实例仍存在”，提供显式清理动作。
- 运行中的本地任务在重启后按现有规则标记中断/失败，并保留可重试信息。
- 服务启动完成后立即执行一次远端句柄核对；核对任务本身不得创建新实例。
- 后端进程退出、异常崩溃或网络断开后，下一次启动必须优先扫描并处理遗留句柄，再允许新的远端任务入队。

### 清理策略

- 所有终态路径统一调用幂等清理函数：正常完成、失败、停止、超时、异常退出、下载失败。
- 删除指令后再次查询实例；只有确认实例不存在才写入 `cleanupState=released`。
- 删除或重试动作遇到清理失败时，保留 `remoteHandle`/`instanceId`，阻止直接再次创建资源。
- 历史记录缺少清理状态时，优先实时核对；不根据本地字段猜测已释放。
- 远端执行器为每个实例设置最长租期和无进展超时；达到任一阈值立即停止远程进程并进入清理流程。
- 远端任务运行期间维护心跳/最后进展时间；看门狗发现任务记录长时间无更新时执行兜底清理，不等待用户手动操作。
- 清理流程最多进行有限次带退避重试；仍失败则保留句柄、标记 `cleanupState=failed`、阻止新实例创建，并将高优先级告警写入任务日志。
- 所有执行器的主流程使用 `try/finally`，无论成功、失败、取消、超时还是下载异常都进入清理；清理完成前不发布“已释放”状态。

### 错误分类

后端保留原始错误用于日志，同时向 UI 提供稳定分类：

- `resource`：库存、规格、实例启动或 SSH。
- `environment`：镜像、CUDA、依赖或运行时。
- `model`：基座模型、Repo ID、下载或路径。
- `adapter`：Adapter 不存在、不可读或产物不完整。
- `training`：训练进程、配置或数据错误。
- `generation`：推理参数、采样或生成过程。
- `download`：结果回传或文件下载。
- `cleanup`：停止/删除/核验失败。

错误响应包含 `failureCode`、`failureMessage` 和 `suggestedAction`；旧的 `error` 字段继续保留。

## API 设计

### 列表与详情

- 视觉任务列表 `GET /api/vision/tasks` 和文生图训练/生成列表继续保留原路径。
- 列表响应只返回摘要字段：ID、名称、状态、进度、当前步骤、更新时间、模型/数据集名称、资源状态和错误摘要。
- 详情响应返回日志、Loss/Eval Loss、产物、完整资源信息、预检快照和失败建议。
- 列表接口统一支持 `query`、`state`、`includeArchived`；已有调用不带参数时行为不变。

### 资源核对与清理

为视觉理解和文生图训练/生成提供统一语义的操作：

- `POST /{task}/reconcile`：只读核对本地记录与优云实例。
- `POST /{task}/cleanup`：执行一次幂等清理并返回核验结果。
- 现有 `stop`、`retry`、`delete` 在进入下一动作前复用相同清理检查。

具体路由前缀沿用各模块现有 API，避免引入跨模块共享路由。

### 文生图结果

生成任务详情增加结果摘要和样本级字段：成功/失败状态、文件名、尺寸、耗时、错误分类、Prompt/Seed/采样参数。成功结果提供预览和下载；失败结果不伪造图片 URL。

## 前端设计

### 任务列表

视觉理解和文生图训练/生成列表统一为：

- 顶部摘要：全部、运行中、成功、失败、待清理数量。
- 搜索：任务名、任务 ID、模型、数据集。
- 状态筛选和更新时间排序。
- 行级操作根据状态显示：详情、停止、重试、克隆、清理、删除。

### 任务详情

详情页采用 NLP 模块的密度和信息层级：

- 顶部显示状态、阶段进度、更新时间和主操作。
- 资源面板显示执行方式、GPU/镜像、实例 ID、资源状态、清理状态。
- 标签页分为“概览”“日志”“指标”“产物/结果”；避免把长日志和配置挤在同一屏。
- 指标至少展示 Step、Loss；启用验证时同时展示 Eval Loss、最佳 Step 和最终 Step。
- 错误面板显示分类、原因和建议动作。

### 样本与结果

- 视觉理解展示 IMAGE_TEXT 样本缩略图、问题/答案和关联图片缺失提示。
- 文生图展示 Prompt、Negative Prompt（如有）、Seed、尺寸、采样参数和生成图画廊。
- 结果下载使用现有安全文件接口，不在前端拼接未校验路径。

## 测试标准与验收门槛

### 后端自动化

- 资源清理：完成、失败、停止、超时、SSH/下载异常均会调用清理；删除后核验实例不存在。
- 幂等性：重复停止、重复清理、重复删除不会重复创建或破坏任务状态。
- 重启恢复：未释放句柄会被核对；不存在的远端实例被标记 `released`；存在的实例不会被静默忽略。
- 状态迁移：非法状态操作返回明确错误；待确认任务不会创建实例；清理失败阻止直接重试。
- 观测数据：Fake 执行器产生的日志、Loss、Eval Loss 刷新后仍可通过详情接口读取。
- 文生图结果：样本成功率、耗时、错误数与结果明细一致；失败样本没有伪造图片。
- 视觉理解：IMAGE_TEXT、模型能力、LoRA/QLoRA、预检和 Best/Final Adapter 校验保持有效。

### 前端自动化

- 列表筛选、搜索、状态标签和数量摘要与接口数据一致。
- 详情页在刷新后仍显示日志、指标、资源和错误建议。
- 状态不允许的按钮不渲染或处于禁用状态；清理失败时显示重试清理入口。
- 图片预览/下载只对成功文件可用，缺失文件显示明确占位状态。

### 受控验收

1. 先运行后端单元/API 测试和前端类型/测试命令。
2. 使用 Fake 执行器跑视觉理解训练、文生图训练、文生图生成全流程。
3. 检查后端重启恢复和历史任务核对。
4. 前述测试全部通过后，使用一台受控优云实例完成真实远端验收：一次只允许一个实例，设置明确的最长租期和总费用上限，记录创建时间、实例 ID、释放开始/完成时间。
5. 验收结束立即停止远程进程并删除实例；删除后轮询优云实例清单，只有确认实例消失才结束验收。
6. 若验收中任一阶段异常、超时或连接中断，立刻触发看门狗清理；清理未确认成功前不得开始下一次验收。

任何硬性门槛失败都回到对应阶段修正，不能以“任务记录已完成”代替远端实例核验；优云清单中存在未释放实例时，验收直接判定失败并先处理资源。

## 分阶段交付

1. **契约与基线：** 补充状态、清理、错误和观测字段测试，锁定现有行为。
2. **后端闭环：** 实现核对、幂等清理、错误分类和日志指标持久化修正。
3. **任务体验：** 统一列表、详情、操作矩阵和错误反馈。
4. **样本结果：** 补充视觉样本预览和文生图结果画廊。
5. **回归验收：** Fake 全流程、重启恢复、必要时受控优云验收。

## 风险与回滚

- 优云 API 暂时不可用时，只记录 `cleanupState=failed` 和句柄，不把实例误判为释放；恢复后可重试核对/清理。
- 历史任务字段不完整时，接口提供兼容默认值，不覆盖原始日志和产物。
- 前端新增字段缺失时显示 `--` 或明确占位，不阻塞旧任务详情。
- 所有改动按阶段提交，若某阶段回归失败，可只回滚该阶段而不影响已有训练产物。
- 真实优云验收采用单实例、短租期和硬超时；验收脚本在进程退出时无条件调用删除与核验，避免测试失败转化为持续计费。
- 看门狗、启动扫描和 `finally` 清理形成三层兜底；任一层失效时，任务仍保持 `cleanup_failed` 和远端句柄，禁止静默放行后续任务。
