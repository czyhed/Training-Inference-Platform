# 视觉理解模型管理界面重构设计

## 1. 背景与问题

当前视觉理解模型管理页同时承担已登记资产管理、优云模型推荐、能力探针说明和注册入口，导致首屏信息过重。四张统计卡、长期展示的说明横幅、七张推荐卡和七列表格连续堆叠，用户需要滚动后才能看到真正需要操作的模型资产。

现有状态表达也不够直接。“仓库候选”“探针通过”是技术状态，但用户真正关心的是模型能否进入本地训练、优云训练和推理部署三个后续流程。优云可用性目前主要由前端推荐模板表达，默认模型列表没有返回后端基于 `YOUYUN_BASE_MODEL_REPOS` 计算的真实结果，容易让推荐状态和实际训练前校验产生认知差异。

## 2. 设计目标

1. 主页面只回答“当前有哪些模型资产、各自能用于什么、下一步需要处理什么”。
2. 将推荐模型发现与已登记资产管理分离，但保持登记流程连续。
3. 使用真实后端状态呈现本地训练、优云训练和推理部署三个出口。
4. 保留探针、路径、能力标签和来源信息，但将低频诊断信息放入详情抽屉。
5. 与 NLP 模型管理保持相同的标题、按钮、表格、抽屉和状态色语言，同时保留视觉模型特有的三出口能力判断。
6. 桌面端提高信息密度，移动端避免依赖横向滚动完成核心操作。

## 3. 选定方案

采用“资产管理主页面 + 基模目录抽屉”的方案 B。

不采用仅清理样式的方案，因为它无法解决推荐目录与资产列表职责混杂，也无法解决状态语义不面向业务出口的问题。不采用双 Tab 页面，因为模型目录是低频辅助入口，独立 Tab 会提高导航成本并制造两个同等级工作区。

## 4. 页面信息架构

### 4.1 页面头部

- 标题：`模型管理`
- 副标题：`管理视觉基模资产，确认训练与推理可用性`
- 主操作：`登记基模`
- 次操作：`浏览基模目录`
- 刷新操作移入列表工具栏，以图标按钮呈现并提供 Tooltip；页面只保留一个刷新入口。

### 4.2 紧凑状态条

删除四张大统计卡，改为一条紧凑状态条，展示：

- 已登记：全部视觉模型资产数量
- 本地可用：可进入本地 LoRA/QLoRA 训练的数量
- 优云可用：后端确认位于 `YOUYUN_BASE_MODEL_REPOS` 的数量
- 待处理：缺少路径、缺少远程配置或探针异常的数量

状态条用于快速判断资产健康度，不承载说明文字，不可替代筛选器。

### 4.3 筛选与搜索

第一行使用分段筛选：

- 全部
- 可用
- 待准备
- 异常

第二行工具栏包含：

- 搜索：模型名称、Repo ID
- 运行环境：全部、本地、优云
- 模型家族：全部、Qwen2-VL、Qwen2.5-VL、Qwen3-VL、自定义
- 参数规模：全部、2B、3B、4B、7B、8B、其他
- 刷新图标按钮

`可用` 表示至少有一个业务出口可用；`待准备` 表示已识别视觉能力但尚未满足任何出口；`异常` 表示未识别视觉模型、路径不存在或探针失败。

### 4.4 资产列表

桌面端表格保留五列：

1. 模型：名称、Repo ID、Revision
2. 来源：本地目录或仓库登记，并显示模型家族与参数规模
3. 可用性：本地训练、优云训练、推理部署三项矩阵
4. 最近检测：后端更新时间
5. 操作：详情按钮和更多操作菜单

主表不再直接展示完整本地路径、全部能力标签、探针长文本和两个并列文字操作。这些信息进入详情抽屉，避免表格宽度和行高失控。

可用性矩阵统一使用三种状态：

- 绿色“可用”：当前条件已满足
- 黄色“待准备”：模型身份有效，但缺少路径或优云配置
- 红色“不可用”：能力不兼容或探针异常

判断规则：

| 出口 | 可用条件 | 待准备条件 | 不可用条件 |
| --- | --- | --- | --- |
| 本地训练 | 本地目录存在、探针通过，并包含视觉语言及 LoRA/QLoRA 训练能力 | 已识别视觉模型但未配置可访问目录 | 未识别视觉语言或探针异常 |
| 优云训练 | 后端 `availableOnYouyun=true`，并包含视觉语言及训练能力 | 已识别视觉模型但 Repo ID 未进入优云可用目录 | 未识别视觉语言或缺少训练能力 |
| 推理部署 | 本地目录存在、探针通过，并包含 `transformers_serving` | 已识别视觉模型但未配置可访问目录 | 未识别视觉语言、缺少服务能力或探针异常 |

移动端将每个模型改为紧凑列表项：模型身份在上，三项可用性纵向排列，底部只保留“查看详情”。不要求用户横向滚动。

### 4.5 资产详情抽屉

详情抽屉按以下顺序组织：

1. 模型身份：名称、Repo ID、Revision、来源
2. 三出口可用性：每项显示状态和明确原因
3. 本地目录：完整路径与复制按钮
4. 能力标签：视觉理解、视觉问答、OCR、LoRA、QLoRA、推理服务等
5. 探针诊断：原始探针状态、最近检测时间、探针说明
6. 操作：重新探针、关闭

本轮不增加跨页面“去训练”“去部署”跳转，避免在当前模块中引入新的导航契约。训练和推理页面继续读取同一模型资产状态。

### 4.6 基模目录抽屉

删除主页面长期展示的七张优云推荐卡，增加右侧 `浏览基模目录` 抽屉。

目录抽屉包含：

- 搜索
- 家族和参数规模筛选
- 推荐模型列表
- 每项展示名称、Repo ID、参数规模、适用场景、资源建议、优云状态
- 未登记模型操作为 `登记`
- 已登记模型操作为 `查看资产`

点击 `登记` 后关闭目录抽屉并打开登记弹窗，自动带入预设；点击 `查看资产` 后关闭目录抽屉并打开对应资产详情。目录中的“优云已就绪”必须来自后端真实可用性；静态预设仅提供名称、规模、用途和资源建议。

### 4.7 登记弹窗

登记弹窗不再重复展示完整七项推荐网格。其职责收敛为确认登记信息：

- 已从目录选择时，顶部显示已选预设摘要
- 支持切换为自定义模型
- 字段：显示名称、Repo ID、Revision、本地目录
- 本地目录为空时明确标记为“仅登记仓库，暂不能本地训练或部署”
- 提交按钮：`登记并检查`

提交后继续调用现有登记接口并执行探针。成功后关闭弹窗、刷新列表，并打开新资产详情；失败时保留表单内容并显示后端错误。

## 5. 数据与接口调整

### 5.1 模型列表响应

`GET /api/vision/models` 的默认响应为每个模型增加：

- `availableOnYouyun: boolean`

该字段由后端 `is_youyun_model_available` 计算。`provider=local` 和 `provider=youyun` 的筛选行为保持不变，避免影响现有训练页面。

前端不读取或推断 `YOUYUN_BASE_MODEL_REPOS`，也不使用静态预设决定已登记资产的远程训练状态。

### 5.2 前端派生信息

模型家族和参数规模由 Repo ID 与预设目录进行保守匹配。无法匹配时显示“自定义”和“其他”，不阻止登记、探针或后续操作。

三出口状态由纯函数派生并单独测试，组件只负责渲染。这样可以避免列表、状态条和详情抽屉出现不同判断。

## 6. 组件边界

继续由 `VisionModelManagementView` 管理页面状态，但将复杂渲染拆为当前文件内的小组件或独立文件，优先保证职责清晰：

- 状态派生函数：模型家族、规模、三出口状态、聚合计数
- 资产工具栏与筛选状态
- 可用性矩阵
- 资产详情抽屉
- 基模目录抽屉
- 登记弹窗

预设元数据继续由 `lib/vision-base-model-presets.ts` 管理。后端模型实体仍由现有视觉模型存储管理，本轮不引入新的数据库表。

## 7. 状态与错误处理

- 初次加载：列表区域显示稳定高度的加载状态，避免页面跳动。
- 刷新：保留当前筛选和搜索，不清空用户上下文。
- 接口错误：在工具栏上方显示紧凑错误条，提供重试；已有数据继续保留。
- 空资产：展示“尚未登记视觉基模”，提供“浏览基模目录”和“登记自定义模型”。
- 无筛选结果：展示“没有符合当前条件的模型”，提供“清除筛选”。
- 探针中：仅锁定当前模型的探针操作，并在该行和详情抽屉同步显示处理中状态。
- 抽屉与弹窗支持遮罩关闭和关闭按钮；表单未提交数据只在主动关闭时丢弃。

## 8. 视觉规范

- 使用现有白色表面、灰色边界、靛青主操作和绿/黄/红状态色，保持与 NLP 管理页一致。
- 卡片圆角不超过 6px；不使用渐变、装饰性大图和嵌套卡片。
- 主页面不使用大面积说明横幅；必要解释跟随具体状态显示。
- 图标使用项目现有图标库；图标按钮提供 `title` 或 Tooltip。
- 表格行高控制在约 68 至 76px，状态矩阵保持固定列宽，避免动态内容导致布局移动。
- 目录抽屉桌面宽度约 720px，详情抽屉约 560px；移动端均占满可用宽度。

## 9. 测试与验收

### 9.1 自动测试

- 后端测试：默认模型列表返回准确的 `availableOnYouyun`；provider 筛选行为不回归。
- 前端纯函数测试：三出口状态、总数聚合、家族/规模识别、筛选组合。
- 现有视觉预设测试：预设元数据和登记回填继续通过。
- TypeScript 检查和 Next.js production build 通过。

### 9.2 页面验收

- 1440px 桌面：首屏能看到标题、状态条、筛选和至少两行资产，不再被推荐卡占满。
- 1024px：工具栏合理换行，表格核心信息不重叠。
- 390px 移动端：资产使用列表布局，无核心横向滚动，按钮和文字不溢出。
- 基模目录：筛选、登记、查看资产路径均可完成。
- 详情抽屉：三个出口状态与原因、完整路径、能力和探针诊断一致。
- 浏览器控制台无错误；刷新、空状态、失败状态和探针处理中状态均可辨识。

## 10. 不在本轮范围

- 下载或缓存新的优云基座模型
- 修改优云实例生命周期或训练执行器
- 修改视觉训练与推理页面的业务流程
- 新增模型删除、归档、重命名或共享存储上传能力
- 为视觉模型建立新的数据库目录服务
