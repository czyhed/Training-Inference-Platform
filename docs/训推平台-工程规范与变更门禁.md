# 训推平台工程规范与变更门禁

> 文档版本：`v1.0.0`  
> 生效日期：2026-09-04  
> 适用范围：Xuntui 训推平台全部前端、后端、数据、训练、推理、优云、部署和运维改动  
> 权威级别：代码变更前必读；与旧说明冲突时，以本文件、当前代码契约和已批准 ADR 中较新的规则为准。  
> 维护原则：规范只记录跨模块、难以从代码直接推断的约束；单文件命令和字段定义仍以代码、OpenAPI、`package.json` 为事实源。

## 0. 强制使用规则

### 0.1 每次代码修改前必须完成

在修改任何源码、测试、配置、迁移或部署文件前，执行并记录以下检查：

1. 阅读本文件中与改动边界相关的章节。
2. 阅读 `README.md`、`CURRENT_STATE.md`、`ARCHITECTURE.md`；若涉及某个模块，再阅读该模块入口和现有测试。
3. 查看 `git status --short`，识别用户已有改动；不回滚、不覆盖无关改动。
4. 明确改动所属边界：前端、API、领域状态、存储、执行器、云供应商、部署或测试。
5. 写出一条可验证的行为假设和一个最小失败测试；无法定义验收条件时先停止编码。
6. 判断是否会创建、占用、上传、下载或释放 GPU/云实例；会则必须先写资源生命周期和兜底路径。

**完成条件：** 变更记录中能指出阅读过的文档、受影响边界、失败测试、风险和回滚方式。

### 0.2 规范词汇

- **MUST / 必须：** 不满足就不能合并或发布。
- **SHOULD / 应当：** 有明确理由才能偏离，偏离必须写入变更记录。
- **MAY / 可以：** 非强制选项，但不得破坏 MUST 约束。
- **事实源：** 对某类数据拥有最终写入和读取权的系统。
- **任务终态：** `completed`、`failed`、`stopped`、`cancelled`、`archived` 之一；终态不可回到运行态。
- **资源终态：** `none` 或 `released`；实例释放确认前不得把任务标记为资源清理完成。
- **可重试错误：** 由错误码/阶段明确定义、重复执行不会产生重复资源或数据的错误。

### 0.3 绝对禁止

- MUST NOT 在未读取本文件和相关模块文档前直接修改代码。
- MUST NOT 把“进程退出”写成“训练成功”；训练成功必须同时满足产物、指标和资源清理条件。
- MUST NOT 在日志、错误响应、报告或测试输出中写入 API Key、数据库密码、MinIO 密钥、SSH 私钥、完整 token 或远端命令中的敏感参数。
- MUST NOT 为了本地演示启动真实 GPU 训练、vLLM 或优云实例；文档、单元测试和 UI 静态检查必须使用 Fake/Mock 边界。
- MUST NOT 使用 `shell=True` 执行用户输入、拼接命令或绕过现有 allowlist。
- MUST NOT 通过重试掩盖数据损坏、权限错误、参数错误或不可重试的供应商错误。
- MUST NOT 删除、覆盖或降级用户已有数据、任务、产物和未提交改动。

## 1. 系统边界标准

### 1.1 分层责任

```text
Browser / Next.js UI
        |
        | HTTP/JSON/SSE；只调用平台 API
        v
FastAPI API / 领域编排
        |
        +-- Domain stores：dataset/task/model/service/evaluation
        +-- Queue/runtime：持久化任务状态、lease、事件、日志、指标
        +-- Storage：PostgreSQL 元数据、MinIO 对象、本地 SQLite 兼容兜底
        +-- Provider boundary：优云 API、SSH、训练执行器、vLLM/Diffusers
```

### 1.2 前端边界

- `app/` 和 `components/` 只负责页面状态、交互、输入提示、展示和调用 API。
- 前端 MUST NOT 直接调用优云 API、ModelScope、MinIO、SSH 或本地文件系统。
- 前端 MUST NOT 自己推断任务成功、实例已释放、模型可用或数据集已发布；这些结论由后端返回。
- 页面显示的状态、日志、loss、价格和资源必须带来源/更新时间；没有真实数据时显示“暂无数据”，不得显示伪造的 0。
- 前端页面切换、轮询和重试必须可取消；组件卸载后不得继续更新 state。
- 新增 API 调用必须进入统一 client/类型定义，禁止在组件中散落硬编码 URL 和重复错误解析。

### 1.3 后端边界

- `backend/app.py` 负责 HTTP 路由、认证入口和领域服务编排，不承担长时间训练、阻塞下载或复杂供应商协议细节。
- 数据集校验、任务状态、模型资产、推理服务和云资源必须由专属模块维护；跨模块操作通过明确接口完成。
- 长任务 MUST 异步化：提交接口快速返回任务 ID，进度通过查询、轮询、SSE 或事件流获取。
- 任何 provider 调用必须经过 `backend/providers/youyun/` 等边界层，不得在业务路由中直接拼优云请求。
- 所有异常必须映射到稳定的内部错误码；外部错误原文只能脱敏后进入诊断详情。

### 1.4 Provider 边界

- Provider 接口 MUST 能表达：创建、查询、连接、执行、停止、删除、清理确认和价格/库存探针。
- 每个创建请求 MUST 带任务 ID、幂等键、区域、规格和超时预算。
- Provider 不得把本地路径直接假设为远端路径；路径必须在上传/挂载阶段显式映射并记录 manifest。
- SSH MUST 使用受信 known_hosts 或固定指纹；禁止自动接受未知主机密钥。
- Provider 错误必须分类为：参数、库存、服务不可用、网络、认证、环境、模型、训练、下载、清理。

### 1.5 存储边界

- PostgreSQL 是共享任务、数据集版本、推理服务和模型文件元数据的首选事实源。
- MinIO 是可复用模型、Adapter、数据集归档和结果对象的事实源；数据库只存元数据和 manifest。
- SQLite 只允许作为明确配置的本地兼容/开发兜底，不得与 PostgreSQL 对同一实体形成无规则双写。
- 本地 `.scratch/` 运行态是诊断缓存，不是生产事实源；清理后不能影响已发布版本和可回放任务。
- 对象上传必须经过 `pending -> uploading -> available/failed` 状态；未完成对象不得在列表中显示为可用。

## 2. 数据传输标准

### 2.1 外部 API 响应格式

新接口 MUST 使用以下结构；旧接口保持兼容时，必须在变更说明中标明未迁移原因：

```json
{
  "requestId": "req-20260904-000001",
  "traceId": "trace-uuid",
  "data": {},
  "error": null,
  "meta": {
    "timestamp": "2026-09-04T18:00:00+08:00",
    "apiVersion": "v1"
  }
}
```

错误响应：

```json
{
  "requestId": "req-20260904-000001",
  "traceId": "trace-uuid",
  "data": null,
  "error": {
    "code": "DATASET_VALIDATION_FAILED",
    "message": "数据集校验失败",
    "details": [{"path": "records[3].image", "reason": "文件不存在"}],
    "retryable": false
  },
  "meta": {"timestamp": "2026-09-04T18:00:00+08:00", "apiVersion": "v1"}
}
```

当前已有未包裹的旧接口不得为了“统一格式”被随意改写；新增字段应优先向后兼容，批量迁移必须单独立项。

### 2.2 字段、ID、时间和数值

- 对外 JSON 字段使用 `camelCase`；Python 内部变量和数据库列使用 `snake_case`；转换只能在 schema/serializer 层完成。
- ID 使用带类型前缀的不可猜测字符串：`ds-` 数据集、`dsv-` 数据集版本、`vt-` 视觉任务、`igt-` 文生图任务、`svc-` 推理服务、`mdl-` 模型、`eval-` 评测、`lease-` 资源租约。
- 所有持久化时间使用带时区 ISO 8601；禁止保存本地无时区字符串。接口默认返回 `+08:00` 或 UTC 并保持一致。
- 金额使用十进制定点或字符串，明确币种和计费单位；禁止用二进制浮点比较价格是否相等。
- 文件大小使用字节整数；像素、步数、样本数、端口使用整数；学习率、dropout、warmup ratio、epochs 等分数使用有限精度十进制。
- `null` 表示明确缺失；空字符串不代表缺失，枚举不得用任意空值绕过校验。
- 哈希统一记录算法名称和十六进制值，例如 `sha256:<64 hex>`；路径记录逻辑相对路径，禁止把本机绝对路径作为跨环境契约。

### 2.3 分页、排序和筛选

- 列表接口 MUST 支持稳定排序；默认按 `createdAt DESC, id DESC`。
- 分页参数统一为 `page`（从 1 开始）和 `pageSize`；`pageSize` 默认 20，上限 100，后端强制限制。
- 返回 `items`、`page`、`pageSize`、`total`、`hasNext`；大数据量场景可另行使用 cursor，但不得同一接口混用两种语义。
- 搜索条件必须服务端校验并记录到请求日志摘要；空查询不得触发全表无上限扫描。

### 2.4 异步任务传输

提交接口返回：

```json
{
  "taskId": "vt-xxxxxxxxxxxx",
  "state": "awaitingConfirmation",
  "executionStatus": "queued",
  "configFingerprint": "sha256:...",
  "message": "任务已进入队列"
}
```

- 创建、确认、重试、停止、删除、清理都是幂等动作；重复请求不得重复创建实例或产物。
- 任务详情必须同时返回 `state`、`phase`、`phaseUpdatedAt`、`lastHeartbeatAt`、`resourceState`、`cleanupState`、`failureCode`、`suggestedAction`。
- 任务日志和指标必须分页或按时间范围查询；单次响应不得无界加载整个历史。
- SSE 事件至少包含 `eventId`、`taskId/serviceId`、`eventType`、`sequence`、`timestamp`、`payload`；客户端必须处理断线重连和重复事件。

### 2.5 错误码标准

错误码采用大写下划线并保持稳定：

| 类别 | 示例 |
|---|---|
| 参数/权限 | `INVALID_ARGUMENT`、`UNAUTHORIZED`、`FORBIDDEN` |
| 数据集 | `DATASET_NOT_FOUND`、`DATASET_VALIDATION_FAILED`、`DATASET_REFERENCED` |
| 模型 | `MODEL_NOT_FOUND`、`MODEL_PATH_INCOMPLETE`、`MODEL_PROBE_FAILED` |
| 任务 | `TASK_NOT_FOUND`、`TASK_STATE_CONFLICT`、`TASK_ALREADY_RUNNING` |
| 资源 | `GPU_UNAVAILABLE`、`INSTANCE_PROVISION_FAILED`、`INSTANCE_RELEASE_PENDING` |
| 训练/推理 | `DEPENDENCY_INSTALL_FAILED`、`TRAINING_FAILED`、`INFERENCE_NOT_READY` |
| 存储 | `STORAGE_UNAVAILABLE`、`OBJECT_UPLOAD_FAILED`、`ARTIFACT_INCOMPLETE` |
| 供应商 | `YOUYUN_SERVICE_UNAVAILABLE`、`YOUYUN_AUTH_FAILED`、`YOUYUN_RATE_LIMITED` |

错误 `message` 面向用户，`details` 面向诊断，禁止直接泄露命令、凭据、远端绝对路径和供应商私密响应。

## 3. 数据模型标准

### 3.1 通用模型原则

- 领域实体必须有稳定 ID、创建者、创建时间、更新时间、状态和版本/指纹字段。
- 可被任务引用的内容必须不可变或版本化；任务引用 `datasetVersionId`、`modelRevision`、`adapterVariant`，不能只保存可变名称。
- 关键关联使用数据库外键或等价引用表；删除采用软删除/归档，禁止直接物理删除仍被引用的实体。
- 状态、错误、清理和产物分开存储；不能用一个 `status` 字段承载所有含义。
- 任何状态迁移记录事件、操作者/来源、原因、时间和 requestId。

### 3.2 Dataset / DatasetVersion

必须至少包含：

```text
Dataset: id, name, modality, structure, owner, lifecycleState, activeVersionId
DatasetVersion: id, datasetId, version, manifestSha256, fileCount, sampleCount,
                validationReport, validatorVersion, storagePrefix,
                createdAt, publishedAt, deletedAt
```

- `modality` 枚举：`TEXT`、`IMAGE_TEXT`、`IMAGE_CAPTION`、`TEXT_TO_IMAGE_DPO` 等；新增枚举必须同步 validator、UI、训练器和测试。
- `structure` 枚举：`SFT`、`DPO`、`CHAT`；任务类型必须与结构严格匹配。
- 发布只允许通过完整校验的版本；发布后版本只读。
- 训练/评测开始后，引用版本不得删除；删除请求返回 `409 DATASET_REFERENCED`。
- manifest 必须包含样本文件、图片相对路径、大小、哈希、数据集格式版本和校验器版本。

### 3.3 TrainingTask

必须至少包含：

```text
id, taskType, modality, datasetVersionId, baseModelId, baseModelRevision,
tuningMode, provider, executionMode, configFingerprint, state, phase,
resourceState, cleanupState, progress, lossHistory, artifactIds,
failureCode, failureMessage, suggestedAction, createdAt, updatedAt
```

- 配置提交后生成 fingerprint；确认时重新计算，变更则必须重新预检。
- `progress` 只能由真实总步数/阶段完成度计算；没有可验证进度时显示阶段，不伪造百分比。
- `completed` 的前置条件：训练进程成功、必需产物完整、manifest 写入成功、资源已释放或明确无资源。
- `failed` 的前置条件：记录 failure code/message，且进入清理流程；没有实例 ID 的创建失败也必须把资源置为 `none`。

### 3.4 ModelAsset / Adapter

- 区分 `base`、`adapter`、`merged`、`metrics`、`manifest`，metrics 不能伪装为权重。
- Adapter 必须记录基座模型 ID、Repo ID/Revision、训练任务 ID、数据集版本、LoRA/QLoRA、rank/alpha/dropout、精度和文件 manifest。
- 只有文件完整、哈希通过、存储状态为 `available` 的模型才能进入推理服务选择器。
- Best/Final 是不同 variant；Best 的选择依据必须记录评测指标和 step，不能只按目录名猜测。

### 3.5 InferenceService

必须至少包含：

```text
id, modality, provider, baseModelId, baseModelRevision, adapterId,
adapterVariant, runtime, runtimeRevision, configSnapshot, state,
exposureState, leaseId, lastReadyAt, failureCode, createdAt, updatedAt
```

- 创建服务不分配 GPU；只有 `start` 才申请资源。
- `ready` 只能在真实 `/health` 和最小推理请求都通过后设置。
- 服务删除前必须停止并释放 lease；归档保留配置、日志、指标和 lineage。
- 对外 API Key 只存哈希/可轮换凭据，响应只返回脱敏前缀和创建时间。

### 3.6 ComputeLease / Resource

- 每个实例/本地 GPU 使用一个 lease：`requested -> provisioning -> acquired -> running -> releasing -> released/cleanupFailed`。
- lease 必须关联 task/service、provider、实例 ID（若已返回）、创建 requestId、租期、最后心跳和清理尝试次数。
- 没有实例 ID不代表可以跳过清理；必须记录“未分配资源”的终态。
- 同一 GPU lease 同时只能被一个训练或推理进程持有。

## 4. 状态机与生命周期标准

### 4.1 数据集状态

```text
draft -> validating -> ready -> published -> archived -> deleted
             \-> validationFailed
```

- `validationFailed` 只能回到 `validating`，不能直接发布。
- `published` 不能原地修改；修改必须新建版本。
- `deleted` 是逻辑状态；存在引用时不得物理清理对象。

### 4.2 训练状态

```text
awaitingConfirmation -> queued -> preflight -> provisioning -> preparing
-> training -> collectingArtifacts -> completed
                                  \-> failed
                                  \-> stopped
```

- 每个阶段必须有进入时间、心跳、超时预算和失败码。
- `provisioning` 失败时必须执行清理 reconciliation；不允许保持“失败但资源 provisioning”。
- `retry` 只能从终态创建新 attempt，禁止覆盖旧日志、manifest 和失败原因。

### 4.3 推理服务状态

```text
stopped -> starting -> loading -> ready -> degraded -> stopping -> stopped
                         \-> failed
```

- `starting/loading` 超时自动进入 `stopping`，释放 lease 后才进入 `failed`。
- `degraded` 可以提供诊断接口，但不能伪装成 `ready`。

### 4.4 优云实例清理规则

1. 创建前生成幂等键并保存。
2. 获得实例 ID后立即持久化，不等待 SSH 成功。
3. 任意失败、取消、超时、进程崩溃或服务重启都写入清理 outbox。
4. 删除调用可重复；“不存在”视为已释放。
5. 删除后查询实例列表或实例详情确认；确认失败保持 `cleanupPending` 并告警。
6. 独立 reconciliation worker 周期扫描 `provisioning/running/releasing/cleanupPending`。
7. 任务只有在资源确认释放后才允许最终归档和计费结算。

**硬验收：** TCP 超时、SSH banner 失败、依赖安装中断、训练进程退出、后端重启、优云 `226645 Service unavailable` 六类故障均必须最终得到 `resourceState=none/released`，且不得重复创建实例。

## 5. 数据集校验标准

### 5.1 分层校验

1. **客户端预检：** 文件扩展名、大小、数量、空文件、重复文件名和基础 JSON 语法提示；不能替代服务端校验。
2. **API 校验：** 解压路径穿越、压缩包大小、成员数量、文件签名、编码、JSONL 行号和字段类型。
3. **领域校验：** 按 modality/structure 执行 schema、图片引用、对话角色、Caption、chosen/rejected、重复样本和数据泄漏检查。
4. **训练前校验：** 数据集版本已发布、manifest 哈希稳定、训练/验证集非空、图片可读取、模型 template 匹配。
5. **远端校验：** 上传后重新计算文件数/哈希/图片可读性；本地通过不代表远端路径可用。

### 5.2 通用规则

- JSONL 每行独立解析；错误必须返回行号、列/字段路径、错误类型、修复建议。
- 禁止静默丢行、自动改写原始文件或用宽松解析吞掉异常。
- 原始上传文件保留；修复生成新版本并保存修复记录。
- 图片仅接受明确白名单格式；校验魔数、解码、尺寸、像素上限、文件大小和扩展名一致性。
- 所有路径规范化后再校验，禁止 `..`、绝对路径、符号链接逃逸和重复目标覆盖。
- 训练集/验证集拆分必须可复现，记录 seed、比例、总数和具体样本哈希。

### 5.3 视觉理解 IMAGE_TEXT

- 每条样本必须有图片引用和至少一轮有效问答/描述；图片路径相对于数据集根目录。
- ShareGPT/Qwen-VL 转换必须保留图像 token、角色顺序和文本内容；不得把图片字段误当成普通字符串。
- `template=qwen2_vl` 只能用于经过对应 processor/model probe 的基座。
- 图片不存在、损坏、超过 `imageMaxPixels`、Caption/回答为空、角色非法、消息顺序错误均为阻断错误。

### 5.4 文生图 IMAGE_CAPTION / DPO

- Caption 经过 Unicode/空白规范化，但原始 Caption 必须可追溯。
- metadata 字段与图片文件一一对应；重复文件名、重复 image hash、孤立图片和孤立 metadata 行必须报告。
- ZIP、图片直传和已生成 metadata 三种入口必须进入同一领域校验器；不能复用纯文本校验器。
- DPO 必须同时存在 prompt、chosen、rejected，且 chosen/rejected 不得完全相同。

### 5.5 校验报告

校验报告必须包含：

```text
datasetId, versionId, validatorVersion, checkedAt, total,
valid, warning, error, fatal, samples, files, imageHashes,
repairableIssues, blockingIssues, sourceSha256
```

报告是只读事实；修复后生成新报告，不覆盖原报告。

## 6. 训练与推理标准

### 6.1 训练提交前门禁

- 数据集版本为 `published` 且结构与任务类型匹配。
- 基座模型 Repo ID、Revision、远端完整路径、tokenizer/processor/config 均通过 probe。
- 镜像包含或明确安装锁定版本的 Python、Torch、CUDA、Transformers、PEFT、TRL、LLaMA-Factory/Diffusers 组件。
- 计算资源库存、价格、显存、磁盘和网络策略已重新验证；预检快照有 TTL 和配置 fingerprint。
- 参数范围、有效 batch size、像素上限、序列长度、验证集数量、输出空间均通过 domain validator。
- 预计失败路径、超时和清理路径已可执行；没有清理策略不得创建实例。

### 6.2 参数标准

- 所有参数必须有类型、范围、默认值、单位和与显存/速度的关系说明。
- `batchSize * gradientAccumulation` 必须展示 effective batch size。
- 学习率、warmup、dropout、epochs 等小数采用十进制解析，不得用字符串拼接 shell 参数。
- 视觉任务必须校验 `imageMaxPixels` 与 GPU 显存的兼容性；超限时提前拒绝或明确降级。
- 保存 checkpoint、日志和评测步数必须能覆盖最小训练任务；不能只在训练结束后才写第一条指标。

### 6.3 训练成功判定

训练完成必须同时满足：

1. 进程返回码为 0。
2. 训练集/验证集指标被真实解析并持久化，或明确标注验证未启用。
3. Best/Final Adapter 或完整权重文件存在，文件数、大小、哈希和 manifest 通过。
4. 产物上传/登记完成；失败则任务不能显示为完成。
5. 优云实例已删除并确认，或本地无租约。

### 6.4 推理 ready 判定

- 选定基座模型和 Adapter 文件完整且 lineage 一致。
- vLLM/Diffusers 进程启动成功，健康接口返回成功。
- 使用最小真实请求完成一次推理；响应格式、超时和错误映射通过。
- 日志、运行指标、模型版本和 lease 已持久化。
- 远端服务停止/失败/超时后，必须先完成实例释放，再允许重启或重试。

## 7. 代码标准

### 7.1 Python/FastAPI

- 使用类型注解、Pydantic schema 和明确返回类型；路由不直接返回任意字典拼接的内部对象。
- 同步阻塞操作不得运行在异步请求线程；长任务进入 runtime/worker。
- 数据库连接、文件句柄、SSH 会话、子进程和临时目录必须使用上下文管理和 finally 清理。
- 外部输入必须在边界层校验；领域层不得假设 UI 已经校验过。
- 错误使用专用异常并映射稳定错误码；日志记录 trace/request/task ID。
- Shell 命令使用 argv 列表和 allowlist；禁止 `shell=True`、用户字符串插入命令或隐式 `bash -c`。
- 远端命令、路径和依赖版本必须可审计；日志只保留脱敏摘要和尾部错误。
- 新增状态迁移必须有正向、重复、非法迁移和重启恢复测试。

### 7.2 TypeScript/React/Next.js

- 开启 TypeScript 严格检查；禁止用 `any` 逃避跨层契约。
- API 响应先通过类型守卫/解析器，再进入组件 state。
- 组件必须处理 loading、empty、error、stale、retry、unmount 五类状态。
- 轮询使用统一 hook，带停止条件、退避和 AbortController；页面卸载必须取消请求。
- UI 状态文案必须来自后端真实状态，禁止把 `undefined`、空数组或失败响应渲染成“成功/0”。
- 样式改动后必须检查桌面和 390px 移动视口；不得依赖旧 `.next` 缓存验证。
- mock 只能在测试 fixture 中使用；生产组件不得引用 `lib/mock-data.ts`。

### 7.3 配置与依赖

- 新依赖必须说明用途、版本、许可证、镜像兼容性、离线/网络要求和回滚方式。
- 训练/推理依赖必须锁版本并记录 Python/CUDA/Torch 兼容矩阵。
- 环境变量必须在 `.env.example` 中声明类型、默认行为和是否必填；真实 secret 只能由部署系统注入。
- 生产缺失必需 secret 必须启动失败；不得静默生成随机 secret。
- API base URL、端口和存储后端只保留一套权威配置；兼容变量必须有迁移期限。

### 7.4 日志与可观测性

- 日志字段至少包括 `timestamp`、`level`、`component`、`requestId/traceId`、`taskId/serviceId`、`phase`、`event`。
- `INFO` 记录阶段转换和关键外部调用摘要；`WARNING` 记录可恢复异常；`ERROR` 记录失败码和清理状态。
- 不记录密钥、Cookie、Authorization、私钥、完整模型下载 URL 中的签名参数或远端命令全文。
- 日志必须区分原始执行器日志、平台事件、训练指标和诊断摘要。
- 日志/指标采用分页、保留期和容量上限；超过上限时压缩或归档，不允许单 JSON 文件无限增长。

## 8. BUG 处理标准

### 8.1 处理闭环

每个 BUG 必须按以下顺序完成：

1. **复现：** 记录精确输入、时间、环境、版本、任务/服务 ID和复现概率。
2. **证据：** 保存 API 响应、脱敏日志、状态快照、关键文件/行号和外部供应商错误码。
3. **根因：** 沿数据流向上追踪到产生错误值的第一处，不以“重试成功”作为根因。
4. **失败测试：** 先添加最小自动化回归测试，证明当前代码会失败。
5. **最小修复：** 一次只解决一个根因，不顺手重构无关模块。
6. **验证：** 运行失败测试、相关单测、类型检查、构建和必要的端到端/故障注入。
7. **资源核对：** 若涉及云/GPU，确认实例、lease、计费状态和任务状态最终一致。
8. **记录：** 更新任务/BUG 条目、变更说明、风险、回滚和剩余限制。

### 8.2 严重级别与响应

| 级别 | 示例 | 响应与门禁 |
|---|---|---|
| P0 | 计费实例无法释放、数据丢失、认证绕过、核心流程阻断 | 立即止血；停止相关发布；修复+故障注入+负责人确认 |
| P1 | 训练/推理高概率失败、状态错误、数据不一致、安全高风险 | 进入近期版本；必须补监控和回归测试 |
| P2 | UI/文档/指标缺口、维护性问题 | 纳入计划；不能引入新的 P0/P1 |

### 8.3 云/GPU BUG 额外规则

- 任何“创建成功后 SSH 失败”“依赖安装失败”“训练超时”“远端进程退出”都先释放实例，再分析训练细节。
- 清理状态为 `pending/failed` 时不得允许无条件重跑；必须先重试清理或经人工确认“无实例”。
- 优云 `226645 Service unavailable`、限流、库存不足等业务错误必须区分为供应商故障，不得归因于数据集或模型。
- 失败任务必须保留 requestId、provider response code、phase、cleanup attempts 和最终 resource state。
- 真实 GPU 验收必须设置总费用上限、超时、自动删除和最终实例列表核对。

### 9.1 测试层级

### 10.2 评审重点

评审顺序固定为：

2. 状态机和幂等性。

6. 测试覆盖、日志和回滚。

### 10.3 发布门禁

- P0 未关闭不得发布。
- P1 必须有明确的风险接受人、监控和回滚方案；核心训练/推理路径上的 P1 默认阻止发布。

- 发布后记录 commit/tag、配置版本、数据库迁移版本、服务健康、错误率和资源实例数。
- 任何真实优云验收都必须在报告中写出开始/结束时间、费用估算、实例 ID（可脱敏）和最终释放证明。

## 11. 当前项目专用约束

- 前端默认端口为 `3100`，后端默认端口为 `8010`；如端口被占用，必须先识别占用进程，不能盲目启动第二套服务。
- README 中的 WSL 后端启动方式依赖 `Ubuntu-24.04`、WSL IP 和 Conda 环境；WSL 不可用时可以使用明确的本地 Python 兼容启动方式，但必须显式设置本地运行目录和存储后端。
- 视觉训练使用 `IMAGE_TEXT` 发布版本、已 probe 的 Qwen-VL 兼容基座和独立视觉队列；不得把视觉任务塞入纯文本任务队列。
- 文生图训练/推理必须区分 Diffusers 镜像、基座模型、Adapter、生成结果和清理状态；只保存配置不应创建实例。
- 优云公共模型库路径必须在远端实例内 probe 通过；本地存在同名 Repo ID 不代表远端可用。
- 远程依赖优先使用锁定的预装镜像；允许下载或在线安装时必须显式配置、记录耗时和网络成本。
- 任何模型、数据集、Adapter 和产物发布都必须可追溯到版本、manifest、哈希和来源任务。
- 本地 fake provider 只用于自动化测试；不能把 fake 验收写成真实 GPU 生产质量结论。

## 12. 反回归不变量

下列不变量被破坏时，变更立即视为未通过：

1. 失败任务不能保持“资源 provisioning”而没有实例 ID。
2. 任务重试不能覆盖旧 attempt 的日志、指标、配置 fingerprint 或 manifest。
3. 未发布/未校验/被引用数据集不能被物理删除。
4. 不完整模型/Adapter 不能进入推理服务选择器。
5. `ready` 服务必须能完成真实最小推理请求。
6. 优云实例删除必须可重复，并最终得到释放确认或明确告警。
7. 前端不能把 API 失败、空数据、未知状态显示成成功或 0。
8. 任何用户输入都不能通过 shell 组合执行。
9. 生产环境缺失必需 secret 不能静默启动。
10. API 错误、日志、审计报告不能泄露密钥和私密远端命令。
